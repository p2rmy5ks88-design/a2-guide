# Build pipeline validation

The previous Android, iOS and desktop workflows watched only `skyline-estates/game.html`. Wrapper/configuration and asset changes could miss native checks. Android/desktop builds also published release files automatically; configured iOS builds could upload to TestFlight. The mobile README described conflicting trigger behavior.

All three workflows now validate relevant pull requests and main pushes, covering game assets, wrappers, shared audio/Firebase settings, their workflow and build guards. Build jobs use read-only repository permissions and do not persist checkout credentials. Signing material is supplied only for an explicitly requested manual publication. Android and desktop publication run in separate dependent jobs with write permission; ordinary builds cannot update release files. Manual `publish` defaults to false. iOS unsigned compilation retains its log and simulator product, propagates failures through piped commands and checks that the app exists.

`tests/build-pipelines.py` exercises representative changed paths, unrelated-file exclusions, default permissions and explicit publication/signing boundaries (34 checks, standard library only). `tests/verify-bundle.cjs` compares the generated wrapper game with the approved source, recursively compares every required local asset/shared audio file, verifies Firebase configuration and all five bundled fonts, and rejects remote font references. The existing build and packaging commands are retained.

Fresh-runner evidence, job links, tool versions and any confirmed compilation fixes are recorded on the associated pull request after validation. Artifacts remain private to Actions access; no release or store upload is part of this milestone. Signed store builds, physical Android/iOS/Steam Deck lifecycle/performance, purchases and multiplayer acceptance remain outstanding. Native dependency versions still use the existing package ranges rather than committed lockfiles; a successful clean run is evidence for that resolved toolchain, not a guarantee for every future dependency version.
