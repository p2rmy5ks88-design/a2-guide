# AETHERFRONT: LAST LINE

Original 3D tower-defense + collectible-squad game for mobile Safari and desktop. Static and
dependency-free at runtime (vendored Three.js r180, ES modules + import map), so it runs from
GitHub Pages at `/a2-guide/aetherfront/` with relative paths only. No backend, no purchases, no
multiplayer.

## Play locally
```bash
cd aetherfront && npm run serve       # → http://127.0.0.1:8787/aetherfront/
```

## Game flow
HOME (portrait) → SQUADS / COLLECTION (portrait) → BATTLE (landscape, rotate prompt in portrait)
→ RESULTS → RETURN HOME (no page reload; progression persists).

* **Roster:** 21 ownable entries (12 units, 7 towers, 2 heroes) + 6 enemies from `data/asset_manifest.json`.
* **Squads:** 5 saved squads, each exactly 5 regular cards + 1 hero, no duplicates, auto-build.
* **Progression:** levels 1–15 with the spec's card/alloy table and stat formulas
  (`damage = base × 1.105^(L−1)`, `hp = base × 1.12^(L−1)`), atomic validated upgrades.
* **Currencies (unambiguous):** *Alloy* (permanent, collection upgrades), *Aether Crystals* (earned
  only), *Battle Alloy* (match-only, Mk I→III field upgrades), *Energy* (0–10, deploys, +1 per 2.4 s).
* **Battle:** straight rigid 18×10 board, BFS routing (towers can never seal the route or trap an
  enemy; units never block), 15 waves with Titan Breaker bosses on 5/10/15, flying enemies, tanks
  that hold enemies, healers/shields, chain lightning, cryo slow, ballistic mortars, hero
  ultimates (Aether Lance row sweep / Orbital barrage on any tile), recall for energy.
* **Save:** `localStorage["aetherfront.save"]`, schema v2 with migration from the prototype's
  `aetherfront-best`, idempotent match rewards (claimed once per match id).

## Code map
| Path | Purpose |
|---|---|
| `src/data.js` | gameplay constants, unit behaviour table, wave composition |
| `src/progression.js` | stat scaling, upgrades, rewards, missions, season track |
| `src/save.js` | schema-versioned store with atomic `transact()` |
| `src/sim/battle.js` | pure deterministic battle simulation (no DOM) |
| `src/render/engine.js` | shared WebGL renderer, adaptive DPR/shadows, GLB library + AnimationMixer |
| `src/render/battle-view.js` | board, calibrated camera fit, picking, actors, health bars, VFX |
| `src/render/home-view.js` | Home 3D diorama |
| `src/render/fallback2d.js` | Canvas 2D view of the same sim when WebGL is unavailable |
| `src/audio.js` | Web Audio buses, iOS unlock, voice limiting, compressor |
| `src/main.js` | screens, navigation, HUD, input |

## 3D assets
* **Meshy AI characters (v3):** `aegis_trooper`, `vesper_ranger`, `sovereign_lyra` and more (see
  `model_source` in the manifest): text-to-3D → PBR texture → auto-rig → animation library, packed by
  `tools/meshy/run-pack.mjs` into the game contract (clips `idle/move/fire/hit/die`, weapon with
  `muzzle`/`flash` nodes on the right hand, 1024 px JPEG textures).
* **Meshy static meshes (v3):** towers, drones, walkers, enemies and the core reactor are Meshy text-to-3D
  PBR meshes wrapped by `tools/meshy/run-static.mjs` with procedural clips (turret recoil, hover, step bob).
* **Delivery compression:** `node tools/compress.mjs` (meshopt + WebP ≤1024 px, keeps marker nodes):
  47 MB → 13.7 MB for all 32 models; a typical first battle downloads ~4–5 MB of models.
* **Preview build:** `node tools/build-preview.mjs` writes `test-results/preview/` with models as embedded
  glTF `.json` for hosts that cannot serve `.glb`.
* **Forge models (v2):** every other asset is generated by `tools/forge` (`npm run forge`) as
  rigid-rig animated GLBs; the forge versions of Meshy-replaced units are kept in `assets/models/forge/`.
* **Starter (v1):** the original handoff GLBs in `assets/models/starter/` (loader fallback).
* 34 WAVs in `assets/audio/` (procedural prototype SFX — studio upgrade still pending).

## Tests
```bash
npm install            # dev only: playwright-core
npm test               # 12 node tests: manifest, BFS, deploy rules, waves, balance, save, rewards
npm run test:browser   # real WebGL (Chrome + SwiftShader) e2e with iPhone viewport emulation
```
Browser tests emulate iPhone viewports in desktop Chrome. **They are not a physical iPhone Safari test.**
